# 第十八轮：精度转换后的有效性校验

日期：2026-09-08。

## 问题与修复

原目标输入助手仅检查转换前有限性，float64 的 `1e100` 转为 float32 后可以
返回无穷大数组。方向权重也只按 float64 检查，`[1e-100] * 3` 在 float32
中全部变成零，原先会继续计算并报告零各向同性。

本轮在复制转换后的目标、初值和坐标变换数组上复查有限性。方向权重同时
校验原值与求解器精度下的值，在 IK、Jacobian 或缓存读取前拒绝溢出及全部
正权重归零。原值校验仍保留，微小负权重不能因转换成负零而被接受。

离线重评的任务权重转换为 float64 后也复查有限性和正权重，避免扩展精度
输入溢出或全量下溢导致报告出现无效归一化。一般浮点舍入和部分分量下溢
仍遵循所选精度；这不是无损精度转换保证。

## 验证

新增 21 项回归：

- NumPy/Torch CPU 的 float32 目标、初值、变换溢出及方向权重溢出、全量
  下溢均在求解和缓存访问前失败，并返回带输入名称的 `ValueError`。
- 公共灵巧度接口在 Jacobian 前拒绝异常权重，包括会转换成负零的微小负数。
- 两个后端的 `[1e-12] * 3` 权重仍得到单位各向同性和约 `1e-12` 的最小奇异值。
- 转换后数组保持独立、连续存储；扩展精度任务权重转换失败不修改源结果。
- 全量 pytest：641 passed、4 skipped；Ruff、51 个 Python 文件格式、完整
  解析工作流、sdist/wheel 构建及 `git diff --check` 通过。

本轮没有运行 CUDA 或远程 CI；没有提交或推送。
